# Architecture

Input flows through deterministic intent and slot resolution, pending continuity, optional advisory semantic resolution, controller routing, task packets, permissions and WriteScope, model/protocol selection, tools, verification, and Experience attribution. A task can stop at a deterministic controller response.

Capability, protocol adherence and result quality are distinct: valid FILE_CONTENT is not proof of correct code. Memory stores project information; Experience records local observations; Community Evidence is a separate, disabled-by-default scaffold. Global controller capability is not authorization for a particular task. Declared capability differs from observed evidence. A write confirmation is not verification; a benchmark is not local live experience. GOOD_ENOUGH favors an adequately evidenced suitable candidate; it does not guarantee the optimum.

Configured profiles declare capabilities and protocol support. Fingerprints tie local observations to model/settings identity; absent or stale evidence should not be treated as success.

## Memory V1

Explicit controller commands write project-bound records; lexical matching and recency select bounded context. A unique, explicit forget request can delete only its matching project record. Sensitive historical records are masked on retrieval rather than rewritten. No full conversation transcript is persisted. Session context, persistent Memory and model Experience use separate state.
